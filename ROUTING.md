# Как выбирать инструменты стартового набора

Это карта для основного ИИ-помощника. Установщик подключает роли и навыки
в Claude Code; в другом клиенте сначала проверь их доступность и способ вызова.
Пользовательская задача и правила проекта определяют объём работы.

## Задача → инструмент

| Задача | Инструмент |
|---|---|
| Один факт, короткая правка, обычная работа с файлом | Основной помощник |
| Исследование с несколькими поисками и источниками | `research` |
| Проверка документа, таблицы или готового результата | `reviewer` |
| Проверка изменений программы | `code-reviewer` |
| Аудит структуры проекта и согласованности его инструкций | `workflow-auditor` |
| Вопрос о возможностях, разрешениях и настройках Claude Code | `anthropic-docs` |
| Сохранение проверенного изменения в Git | навык `commit` |
| Подключение или диагностика MCP в Claude Code | навык `install-mcp` |

Не передавай каждый простой поиск исследователю и не вызывай весь набор
проверяющих автоматически. Отдельная роль полезна, когда её работа имеет
ясный вход и самостоятельный результат либо требует много исходных материалов.

## Передача задачи

Передай специалисту цель, нужные файлы, ограничения и формат ожидаемого
результата. Дай контекст, необходимый для проверки фактов и соответствия
заданию. Читательскую оценку без объяснения авторского замысла можно запросить
отдельно; она не заменяет сверку требований и источников.

Независимые проверки одного стабильного результата могут идти параллельно.
Зависимые действия выполняются последовательно: сначала собрать факты,
затем сделать работу, потом проверить изменённые свойства.

## Глубина проверки

- Небольшая обратимая правка: прямая проверка изменённого места.
- Новый документ или функция: сверка с заданием, подходящие проверки фактов,
  тесты или визуальный просмотр.
- Деньги, договоры, персональные данные, удаление или production: первичные
  источники, границы разрешённого действия и независимая профильная проверка,
  когда она снижает конкретный риск. Общий reviewer не заменяет специалиста
  в предметной области.

Находку подтверждай файлом, строкой, воспроизведением или открытым источником.
Непроверенную часть называй прямо. Исправления проверяй в затронутых местах;
не запускай полный цикл заново после каждой косметической правки.

## Полномочия и результат

Просьба проверить означает чтение и отчёт. Просьба исправить разрешает
необходимые изменения в указанном объёме. Не превращай аудит в реорганизацию,
а установку одного инструмента — в перенастройку всего компьютера.

Не открывай секретные файлы ради общего обзора, не показывай ключи в отчётах.
Внешние действия — push, публикация, отправка, платные операции и изменения
доступов — выполняй в пределах явного разрешения пользователя. Учитывай уже
данное разрешение, не запрашивая его повторно.

В конце сообщи результат, файлы, фактические проверки и оставшиеся ограничения.
Локальный коммит, отправка на сервер и работающая интеграция подтверждаются
отдельно: одно не доказывает другое.
