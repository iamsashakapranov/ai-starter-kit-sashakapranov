# Подготовка проекта

Работай в выбранной пользователем папке, существующей или пустой. Сначала разреши
путь и убедись, что выбран именно этот проект. Если путь неоднозначен, уточни его
до записи. Не создавай структуру соседнего проекта и не переноси его правила по умолчанию.

## Осмотреть перед изменениями

Прочитай входной README, действующие AGENTS.md/CLAUDE.md и инструкции родительских
каталогов, если они применимы. Посмотри верхний уровень, конфигурацию проекта и
скрипты, необходимые для понимания работы. Если это git-репозиторий, проверь ветку,
дерево и индекс; сохрани чужие изменения.

Установи назначение проекта, важные исходники, способ запуска и доступные проверки
из файлов или слов пользователя. Не запускай проект только ради знакомства.
Не открывай секреты и личные материалы, не относящиеся к подготовке.

## Добавить только необходимое

- Если AGENTS.md уже есть, используй его. Меняй только подтверждённый пробел в рамках
  запроса, сохраняя существующие правила; не заменяй файл шаблоном.
- Если AGENTS.md нет, создай короткий вход: назначение и границы проекта, где искать
  основные материалы, какие оригиналы сохранять и как проверить результат.
  Включай только сведения, которые удалось установить.
- Команды запуска и проверок бери из реально существующих скриптов, конфигурации
  или документации. Не придумывай `npm test`, `pytest` или сборку по одному расширению
  файлов. Если команды не установлены, прямо это обозначь, без пустых заглушек.
- Если проект готовится для Claude Code и ему нужен вход CLAUDE.md, добавь короткий
  указатель на AGENTS.md, например `@AGENTS.md`. Существующий CLAUDE.md сохрани;
  не создавай вторую копию общих правил и проверь, что указатели не образуют цикл.

Для пустой папки достаточно подтверждённой цели и кратких правил работы с будущими
материалами. Не выбирай стек, не создавай исходный код и не запускай git init,
установку зависимостей, подключение сервисов или публикацию без такого поручения.
Сам запрос на подготовку разрешает нужные локальные правки инструкций; отдельное
одобрение каждого нового файла не требуется.

## Проверить понятность

Прочитай получившийся diff и проверь существование всех указанных путей. Выполни
одну простую задачу без правок, например: «По инструкциям проекта найди основной
исходник и объясни, как проверить изменение». Для пустой папки — «Назови назначение
папки и какие решения ещё не приняты». Ответ должен опираться на реальные материалы,
а не догадки; новая сессия или платный вызов для такой проверки не нужны.

В результате перечисли изменённые файлы, проведённую проверку и оставшиеся неизвестные.
Не утверждай, что клиент уже перечитал инструкции, если это не проверено.
