# Подключение MCP в Claude Code

Работай с конкретным сервисом и задачей пользователя. Этот навык описывает
Claude Code; команды и настройки другого клиента нельзя подменять этим форматом.

## Сначала установить причину и способ подключения

- Уточни клиент, ОС и рабочую папку по доступному контексту. Проверь наличие
  `claude` и версию; перед командой сверяй её параметры через `claude mcp --help`
  и справку нужной подкоманды. Не устанавливай CLI только ради диагностики.
- Проверь, не подключён ли сервис уже. Наличие записи в настройках, доступность
  сервера и успешный вызов нужной функции — разные результаты проверки.
- Открой [официальную документацию MCP](https://code.claude.com/docs/en/mcp)
  и инструкцию самого сервера. Выбирай подтверждённый endpoint или пакет;
  не подставляй по памяти случайный пакет с похожим названием.
- Определи транспорт и требуемую авторизацию. Node, Python, Docker и другие
  зависимости нужны только соответствующим локальным серверам. Удалённый HTTP
  сервер не требует установки локального npm-пакета.

## Область установки

| Scope | Доступность |
|---|---|
| `local` | Только пользователю в текущем проекте; значение по умолчанию |
| `project` | Участникам проекта через `.mcp.json` |
| `user` | Пользователю в разных проектах |

Не расширяй область подключения без необходимости. Перед изменением существующей
записи сохрани её прежний вариант для отката в разрешённом приватном месте.
Не выводи значения credentials из конфигурации в чат, diff или журнал.

Примеры формы команды, **не готовые подключения**:

```bash
claude mcp add --transport http --scope local example https://mcp.example.com/mcp
claude mcp add --transport stdio --scope local example -- /absolute/path/to/server
```

После `--` идут команда сервера и её аргументы. Для запуска через `npx` используй
пакет и способ запуска из документации поставщика; для воспроизводимости фиксируй
проверенную версию. Не выполняй установочные скрипты из результатов поиска без чтения.

Ключи не вставляй в командную строку, историю shell и отслеживаемые файлы.
Выбери поддерживаемый поставщиком механизм OAuth, переменных окружения или
защищённого хранилища. Не проси прислать действующий секрет в чат.

## Проверка и устранение сбоев

1. При запросе «проверь» ограничься диагностикой. При запросе «подключи/почини»
   сделай необходимое изменение в уже разрешённом объёме.
2. Проверь статус в `/mcp` и доступность ожидаемых инструментов. Выполни один
   безопасный вызов чтения на разрешённых данных, если он доступен и нужен
   для проверки. Платные вызовы и записи во внешние системы требуют авторизации.
3. Если не работает, раздели причины: команда не запускается, отсутствует
   зависимость, сеть недоступна, не пройдена авторизация, не хватает прав,
   сервер подключён в другой области или клиент ещё не загрузил конфигурацию.
   Читай только нужные диагностические сообщения, скрывая секреты.
4. Исправляй подтверждённую причину. Не повышай таймауты и лимиты вывода наугад,
   не удаляй другие подключения и не отключай проверки доступа.

В результате укажи, что изменено, где действует подключение, какой вызов
проверен и как вернуть прежнюю настройку. Если проверена только конфигурация,
так и напиши: это ещё не доказательство работающей интеграции.
