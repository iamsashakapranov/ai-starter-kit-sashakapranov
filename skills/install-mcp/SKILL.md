# Подключение MCP

Работай с выбранным сервисом и задачей пользователя. Установка набора инструкций
не означает разрешение подключить все упомянутые сервисы.

## Выбрать клиент и маршрут

Определи из контекста приложение, ОС и рабочую папку. Если от неизвестного
клиента зависит команда записи, уточни его до изменения.

- Claude Code → [инструкция Claude](references/claude.md).
- Codex → [инструкция Codex](references/codex.md).

Читай только нужный маршрут. Сверь его с локальной `--help` и актуальной
документацией поставщика сервера. Не переноси CLI-флаги и scope между клиентами.
При недоступном CLI сначала выясни, можно ли решить задачу через интерфейс
приложения; запрос на диагностику не разрешает устанавливать CLI.

## Проверка перед подключением

- Определи, какое действие нужно: запрос «проверь» означает диагностику,
  «подключи/почини» — необходимые изменения в разрешённом объёме.
- Проверь, не подключён ли сервис уже и в какой области он доступен. Существующий
  плагин или connector может уже решать задачу: не создавай второй маршрут без причины.
- Открой официальную инструкцию сервера. Проверь endpoint/пакет, способ запуска,
  авторизацию и нужные права. Node, Python и Docker нужны лишь соответствующему
  локальному серверу, а не любому MCP-подключению.
- Сохрани прежнюю изменяемую запись для отката в разрешённом приватном месте.
  Не копируй всю домашнюю конфигурацию, историю и credentials ради одной настройки.

Ключи не вставляй в командную строку, чат, shell history и отслеживаемые файлы.
Используй поддерживаемый OAuth, окружение или защищённое хранилище. Не печатай
нефильтрованную конфигурацию: она может содержать токены. Проверку прав или
подозрительной команды можно передать `security-reviewer`; это не обязательный
этап для каждого обычного подключения.

## Проверить результат

Разделяй уровни: запись в конфигурации → загрузка сервера → доступность инструмента
→ успешный вызов нужной функции. Выполни один безопасный вызов чтения на разрешённых
данных, если это доступно и входит в задачу. Платный вызов и внешняя запись требуют
соответствующего разрешения. Наличие имени сервера не доказывает рабочую интеграцию.

При сбое отдели запуск процесса, зависимости, сеть, авторизацию, права, область
настройки и перечитывание конфигурации. Исправляй подтверждённую причину;
не повышай таймауты наугад, не удаляй соседние подключения и не отключай защиту.
Если повторная попытка с тем же условием не дала новых данных, сообщи конкретное
ограничение вместо бесконечных переустановок.

В отчёте: что изменено, для какого клиента и области, какая функция проверена,
что осталось неизвестным и как вернуть предыдущую настройку.
