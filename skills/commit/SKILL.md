# Commit

Автоматический коммит, пуш и бэкап .env в iCloud.

## Когда вызывать

- Добавил новую функциональность
- Исправил баг
- Обновил конфиг, документацию, директивы
- Закончил рефакторинг
- В конце рабочей сессии (если были изменения)

**Без вопросов.** Не спрашивай "сделать коммит?", "запушить?", "какое сообщение?" — просто делай.

---

## Workflow

### Шаг 1: Проверить статус

```bash
git status
```

Если нет изменений — ничего не делать, выйти.

### Шаг 2: Собрать пути СВОЕЙ задачи и добавить их

Определи, какие файлы относятся именно к твоей задаче (обычно это одна папка проекта). Запомни эти пути — они нужны и для `add`, и для `commit` (шаг 3).

```bash
git add <пути своей задачи>
```

**ВАЖНО — НЕ использовать `git add .` / `git add -A`.** Добавлять только конкретные файлы/папки своей задачи по именам.

**Почему точечно (главное):** в одной папке репозитория несколько окон Claude делят ОДИН общий git-индекс. В нём могут висеть чужие staged-правки из других окон (параллельная работа над другими проектами). `git add -A` сгребёт это чужое к тебе в коммит.

**Что НЕ коммитить:**
- `.env`, секреты, токены, ключи
- `tmp/` — временные файлы
- `__pycache__/`, `.DS_Store`

### Шаг 3: Коммит — ОБЯЗАТЕЛЬНО с указанием путей

```bash
git commit -m "Описание" -- <те же пути своей задачи>
```

**Критично:** коммить с явным перечислением путей (`-- path1 path2 …`), а НЕ голым `git commit -m "…"`.
Голый `git commit` заметает **весь индекс** — включая staged-правки из других окон → в твой коммит попадёт чужое (реальный баг, ловили 13.07.2026: коммит про транскрипт прихватил чужие удаления из соседнего окна).
С путями git берёт **ровно указанное**, что бы ни висело в общем индексе.

Перед коммитом не лишне глянуть `git status` — если в индексе (`Changes to be committed`) есть staged-файлы НЕ из твоей задачи, это чужое из другого окна: не трогай их, просто коммить свои пути.

**Формат сообщения:**
- На **русском** языке
- Короткое описание что сделано (1 строка)
- Без префиксов (feat:, fix: и т.д.)
- Примеры: "Добавлен парсер YouTube", "Исправлен баг в экспорте", "Обновлён CLAUDE.md"

### Шаг 4: Пуш

```bash
git push
```

- Если remote не настроен — сообщи пользователю, не падай
- Если пуш не прошёл (нет прав, конфликт) — сообщи и предложи решение

### Шаг 5: Бэкап .env (опционально)

```bash
BACKUP_ROOT="$HOME/.env-backups"   # ← замените на свой путь, если нужен другой
PROJECT_NAME=$(basename "$PWD")
BACKUP_DIR="$BACKUP_ROOT/$PROJECT_NAME"
mkdir -p "$BACKUP_DIR"
cp .env "$BACKUP_DIR/.env"
```

- Проверь есть ли `.env` в корне проекта
- Если нет — пропустить этот шаг
- Путь бэкапа настройте под себя (iCloud, Dropbox, локальная папка и т.д.)

## Правила

- Работай в **текущей ветке** — не создавай новые без просьбы
- **Всегда коммить с явными путями** (`git commit -m "…" -- <пути>`) — защита от захвата чужих staged-правок при параллельной работе в нескольких окнах Claude (все окна одной папки делят один индекс)
- Для полной изоляции параллельной работы есть скилл `worktree` (отдельная папка+ветка на проект)

## Checklist выполнения

- [ ] git status — есть изменения; заметил ли чужие staged-файлы из других окон (их не трогать)

- [ ] git commit -m "…" **-- <те же пути>** (с явными путями!) на русском
- [ ] git push
- [ ] Бэкап .env (если .env есть)
